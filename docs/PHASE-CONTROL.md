# RemoteDesk control channel — Phase 5

## Purpose

Use OBS + MediaMTX exclusively for screen capture and H.264 delivery. Use the Rust Host only for owner-approved mouse/keyboard input. The control data path is:

`iPhone Safari -> WSS Cloudflare Worker -> Durable Object WebSocket pair -> Windows Host -> Enigo -> Windows input APIs`

## Commands

The Worker accepts only the following bounded messages from an authenticated client:

- `move`: relative cursor movement, at most 180 px per message per axis.
- `click`, `buttonDown`, `buttonUp`: left, right, middle mouse buttons.
- `wheel`: bounded vertical scroll.
- `key`: down/up/click for an allow-list of common navigation and modifier keys, function keys, and alphanumeric keys.
- `text`: Unicode text, maximum 500 characters.
- `releaseAll`: releases held keys and mouse buttons.

Every input command is validated in both the Worker and Host. The Host requires terminal approval before it joins the control WebSocket. Arbitrary shell execution and file operations are not exposed.

## Test checklist

1. Run `npm.cmd run typecheck` inside `worker/`.
2. Deploy the Worker with `npx.cmd wrangler deploy`.
3. Wait for Pages deployment.
4. Start the Host with `REMOTEDESK_API_URL` set to the deployed Worker URL.
5. Enter the new code on the Pages site and approve it in the Host terminal.
6. Verify the status changes to `Управление подключено`.
7. Test trackpad movement, left/right click, scroll, a special key, and text entry.
8. Close the browser tab and verify the Host releases held keys/buttons.
9. Test MediaMTX video in a separate tab. The video path is not proxied by the control Worker.

## Deployment caution

The browser source contains no Host secret. A client token is generated by the pairing API, and control sessions are accepted only after the Windows terminal approval. Do not disable this approval or expose the Host process with an unauthenticated inbound port.
